barzel-cluster — admin portal

One place to start for every service of this environment. The links are relative: the same page serves each environment under its own host name.

You signed in with GitHub to see this page. Argo CD and Grafana sign you in again through the same identity; your GitHub team gives your access there: brzl-admins, brzl-operators or brzl-auditors. Sign out.

Services

ServiceWhereNotes
Argo CD/argocd/ GitOps: what is deployed, from which revision. Press "Log in via GitHub".
chofesh/apps/chofesh/ The example app: a Sefaria search page with its own Postgres (tzvat/chofesh). Workloads are outside sign-on.
Grafana/grafana/ Metrics, and the logs of the two log stores: the admin log store (the records that audit this environment) and the diagnostic log store (the detailed logs of the workloads and the platform).

Command line

The CLI tools are in the kiesei image, with the same host name and kubeconfigs as the driver. Open a shell in it from the repository: bash driver/kiesei.sh shell. The HTTP tools use this same host; kubectl and bao keep their own endpoints (the kubeconfigs in the run directory; the store's port on the driver's machine).

# Argo CD CLI, through the portal, signed in with GitHub (in the kiesei
# shell: open the URL it prints in your browser)
argocd login HOST --grpc-web-root-path argocd --sso --sso-launch-browser=false

# the cluster, as yourself: kubelogin signs you in through Dex, one time
export KUBECONFIG=var/run/ENV/current/kubeconfig-sign-on
kubectl auth whoami
kubectl get applications -n argocd

# in an emergency, without sign-on: the cluster-admin kubeconfig
export KUBECONFIG=var/run/ENV/current/kubeconfig
argocd --core app list

# the cluster secret store (local: OpenBao beside the cluster)
BAO_ADDR=http://127.0.0.1:8200 bao status

Replace HOST with this page's host name and ENV with the environment's name.
